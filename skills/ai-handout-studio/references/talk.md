# 登壇スライドを組む

人前で話すためのスライド(登壇・LT・講義)を `deck.json` で組む。**読ませる資料ではなく、話し手が話しやすく、聞き手が「いまどこの話か」を見失わない紙芝居にする。**

書き方の土台(コマンド・座標・ブロック)は [SKILL.md](../SKILL.md)。ここには登壇に固有の決まりだけを書く。見た目は登壇用テンプレートの Podium(白地に深紅。本文 32px・見出し 44px・表紙 72px)を使う。利用者が別のテンプレートを名前で挙げたときだけ、そちらにする。

## 作る前の聞き取り

書き始める前に、[SKILL.md](../SKILL.md) の「作る前の聞き取り」に次の項目を足して、同じ質問票(question-sheet スキル)で1回にまとめて聞く。いきなり `deck.json` を書かない。

| 項目 | 聞くとき | 聞き方 |
| --- | --- | --- |
| 告知ページ | 会話に URL が無いとき | 自由入力(URL)。あれば読んで正式な題・概要・持ち時間を取り、聞かない。応募時の下書きで代えない |
| 持ち時間 | 会話から決まらないとき | 自由入力(分)。SKILL.md の「枚数」にあたる |
| 伝えたいこと・聞き手・驚かせどころ(どの話で「おっ」と思わせるか) | 会話から決まらないとき | 自由入力 |

## 作る順番

答えを受け取ったら、1〜3を利用者と済ませる。

| 順 | すること |
| --- | --- |
| 1 | 骨子を利用者と合意する。骨子はスライドごとの `heading` の `text` を並べたもの。告知で約束した論点が入っているかをここで照らす |
| 2 | そのスライドでしか成り立たない中身(図・具体例・数字・実物の画面)を決める |
| 3 | 体裁(ブロックの種類と座標)はそのあと。完成したら、告知の論点がどこかに載っているかをもう一度照らす |

- 出発点は構成 `talk` とテンプレート `podium`(`ai-handout-studio new --title <題名> --outline talk --template podium`)。表紙 / 自己紹介 / つかみ / 中扉 / 本文 / 本文 / 中扉 / 本文 / まとめ / 締め の10枚が置かれる。持ち時間に合わせて本文と中扉を足し引きする
- 型に中身を流し込まない。`card-grid` の3枚並べを何枚も続けると、整って見えて何も伝わらない
- 提案書のように読んで理解させる資料の部品(カードの並び・対比の枠・手順の図)を1枚に詰めない
- 数字・固有名詞・日付は利用者から出たものだけを使う。無いものは `[[要確認]]`

## 骨格

| 場所 | layout | 決まり |
| --- | --- | --- |
| 表紙 | `cover` | 題は告知ページの正式な題のまま |
| つかみ | `content` | 聞き手のいまの状況から入る(困りごとの代弁・問いかけ・最近の出来事・自分の近況)。言葉の定義から始めない |
| 中扉 | `section` | 直前までの話を聞いた人が次に知りたくなることを、問いかけの一文で `heading` の `text` に書く。`kicker`・番号・補足の行は付けない |
| 本文 | `content` | 中扉の直後の1枚は、その問いへの答えにする。答えの続かない中扉は取り除く |
| 締め | `closing` | 聞き手にしてほしい行動を一言で |

- 中扉は本文3〜6枚ごとに1枚。中扉を続けるのは2枚まで。構成 `talk` の骨組みは本文を省いてあるので、本文を足して中扉の間を3〜6枚に広げる
- 話す項目の一覧や結論を先に見せない(目次のスライドも置かない)。問いを立てたら、答えは次のスライドで開く
- 仕組みの説明は、抽象 → 具体例 → たとえ の順に進める。主張とその実例は隣のスライドに置く

## 1枚の量

| 項目 | 決まり |
| --- | --- |
| 量 | `heading` 1つに本文は4行まで。はみ出す分は次の1枚へ回す |
| 本文 | `text` か `bullets`(3〜4項目、階層なし)を1つ |
| 強調 | 太字や色で目立たせるのは1枚に1か所まで。目立たせない本文スライドのほうを多くする |
| 図 | 1枚に1つ(`image` か図のブロック)。図が主役の1枚は、文字を見出しと一言の前置きだけにする |
| 表 | `table` は列を3つまでに抑える |
| 注記 | 見て分かることを小さな字で書き足さない。画像に「これは◯◯です」を添えない |

字の大きさは登壇用テンプレートの目安(本文 32px・見出し 48px・表紙 64px)で高さを取る。本文 32px は1行およそ 52px、全角でおよそ `w / 32` 文字。本文3〜4行なら `h` は 256px 前後。

## 見出し

- `heading` の `text` は、その1枚の主張を一文で。スライドが切り替わってすぐ論点が伝わるようにし、1行に収める。項目名(「背景」「課題」)にしない
- 書き方を混ぜる。常体の言い切り・敬体・体言止め・問いかけ(〜の？)・「！」を、1枚ごとの役割で選ぶ

| その1枚の役割 | 書き方 |
| --- | --- |
| 図や画面が主役 | 体言止めの短い名札(3〜6字でよい) |
| 主張・気づき | 常体の言い切り |
| 驚き・転換 | 「！」で言い切る |
| 反論への切り返し・締め | 敬体 |
| 中扉 | 聞き手の心の声を問いかけで |

- 口語の砕けた語尾(〜てる・〜ばいい・〜んです)は使わない。敬体で考えた文の語尾だけを常体に付け替えない。常体にしたいなら体言止め・「〜しよう」・「！」で作り直す
- 書き終えたら、全スライドの `heading` の `text` を通しで並べて数える。「！」「？」・敬体がほとんど無い、長さが全部そろっている、同じ接続詞や「◯◯:」で始まる見出しが3枚以上続く、のどれかなら偏っている

## 図

- 図が主役か文字が主役かを先に決める。図が主役なら幅いっぱいに大きく、文字が主役なら図は挿絵の大きさ(幅 100〜330px)で右下の空きに置く
- 要素を足す前に、それが無くても図が伝わるかを考える。箱の名前の下に説明の小さい行を入れない。図の中に文を書かない。言いたい文は `notes` に書いて口で言う
- 横に並ぶ要素は3つ前後まで。4つを超えたら近いものをまとめる
- 仕組みの図は、同じ図を3〜5枚に分け、要素を1つずつ足していってもよい
- 図の中の字は、投影したときに本文と同じくらい読める大きさにする。収まらないときは、文言を削る → 箱を広げる → 図を大きくする の順で直す
- 挿絵は、本文に出てくる物や人をそのまま表すものに限る。場の雰囲気づくりのためには置かない。毎枚には置かない

## 台本(notes)

- 各スライドの `notes` に、そこで話す言葉を話し言葉で書く。箇条書きのメモではなく、声に出して読める文にする
- 10〜20分の枠なら、本文1枚につき150字前後
- スライドに書いたことをそのまま読み上げる台本にしない。スライドに載せなかった説明・たとえ・実話を `notes` に回す
- 表紙・中扉・締めの `notes` は一言でよい

## 尺

| 数えるもの | 目安 |
| --- | --- |
| 本文(`content`)1枚 | 30秒 |
| 表紙・中扉・締め(`cover` / `section` / `closing`) | 8秒 |
| `notes` があるとき | 毎分300字で数える |
| デモ・質疑 | 枚数とは別に、固定の時間として足す |

- 持ち時間の9割に収める。15分の枠なら13分半まで
- 骨子を決めたときと、完成したときに見積もる。はみ出したら、削れそうな本文を2〜3枚挙げて利用者に選んでもらう。中扉は削らない

## 検品

`ai-handout-studio check <path> --minutes <持ち時間>` を実行し、尺の見積りと警告(本文が多い・図が2つ以上・見出しの単調さと口語の語尾・ノート空)を確かめる。exit 0 のあと、次を1枚ずつ見る。

1. 本文が4行を超えたスライドが残っていない
2. `heading` が「背景」「課題」のような名札だけになっていない。通しで並べて書き方が偏っていない
3. 図と強調は、どのスライドも1つずつまで
4. 問いかけの中扉のあとに、その答えを出すスライドが続いている
5. 予告・結論の先出しが紛れていない
6. 告知で約束した論点がどれかのスライドに載っている
7. 尺の見積りが持ち時間の9割に収まっている
