# 読み手のメモ

同じ人に何度も資料を渡すとき、その人について分かったことを残して、次の資料で使い直す。資料に**何を書かなくてよいか**と、**どこを厚く書くか**を決めるためのメモ。

- 置き場所: `ai-handout-studio open` の出力の `readers` の場所に、`<読み手>.md` で1人1ファイル。名前は英小文字とハイフン(`tanaka-pdm` など)。資料と同じく git に入らない
- 読むとき: 資料を作る前(HTML 資料の手順1、スライドと質問票の聞き取りの前)。メモに書いてあることは聞かない
- 書くとき: 新しい読み手なら、聞き取りの前に仮のメモを作る(答えを待つ間に、何を推測していたかが残る)。答えや読者テストで分かったことで直す

## 形

```md
# <読み手>

- 役割: <資料を読む立場。例: 決済チームの PdM>
- 更新: <YYYY-MM-DD>

## 知っていること(事実)
- <確かめたことだけ。出どころを添える。例: 社内の設計書を毎週読んでいる — 本人の回答>

## 知っていること(推測)
- <確かめていないこと。答えが来たら上へ移すか消す>

## 怪しいところ
- <使えるが意味を判定できないもの、前に詰まったところ。資料の芯になる>

## 読み方
- <読む時間、図から入るか文から入るか、スマホで読むか>

## 資料で省くもの
- <「知っていること」から導く。例: 用語の定義、道具の入れ方>

## 未確認
- <答えで資料の中身が変わる質問だけ>
```

## 決まり

- 書くのは仕事で資料を読むのに要ることだけ。私生活や仕事に関係の無いことは集めない。本人に見せられない内容は書かない
- 事実と推測を同じ欄に混ぜない。依頼や会話に無い経歴を、事実の欄に書かない
- 読者テストで読み手が分からなかった語が「知っていること」にあれば、そのメモが間違っている。直す
- 1回きりの読み手(初めて渡す相手で、次が無い)には作らなくてよい
