# 図を作る

構造を文章や表より速く伝えたいときに使う。図の中身を JSON で書くと、生成器が配置を決め、同じ見た目の PNG・SVG・HTML に書き出す。座標と色は書かない。以下の `<diagram>` は、この SKILL.md があるディレクトリに置き換える。Node.js 22 以上が要る。

## 図にするか決める

図にするのは、文章だと読み手が頭の中で組み立て直すものだけにする。手順が分かれて合流する、誰の手を渡るかが変わる、部品どうしのつながりが変わる、のどれか。並びが1本の手順や、項目を並べるだけなら、番号付きの箇条か表で足りる。

読み手が図から判断を読み取れるようにする。題(`title`)には何の図か、説明(`caption`)には図から何を読み取ってほしいかを1〜2文で書く。説明の書けない図は載せない。1つの決定に図は1枚まで。

## 種類を選ぶ

| 種類 | 使うとき | 例 |
| --- | --- | --- |
| 流れ(`flow`) | 手順・分かれ目・合流。誰が行うかで分けるならレーン、段階で区切るなら段階 | [役割で塗る](examples/flow-roles.json)・[レーン](examples/flow-lanes.json)・[レーン × 段階](examples/flow-lanes-phases.json)・[変わるところ](examples/flow-change.json)・[縦の短い流れ](examples/flow-down.json) |
| 構成(`structure`) | 部品と、そのつながり。持ち主や実行環境の境界を囲みで示す | [部品と囲み](examples/structure.json)・[囲みを積む](examples/structure-stacked.json)・[戻る線と輪](examples/structure-cycle.json)・[英語](examples/structure-en.json) |
| 比較(`compare`) | Before / After。同じ種類の図を2枚並べる | [比較](examples/compare.json) |

シーケンスや状態の移り変わりは描けない。archify(別の作者のスキル)が入っていれば、そちらを使う。

## JSON を書く

どの種類も `type`・`title`・`caption` を持つ。

- 箱(`nodes`): `id`・`label`・`sub`(補足の1行)・`role`・`change`
  - `role` は見分けたいものだけ: `user`(利用者)・`screen`(画面)・`process`(処理)・`decision`(判断)・`data`(データ)・`output`(出力・通知)・`external`(外部)
  - `change` は `new`・`changed`・`removed`。1つでも付けると、色は役割ではなく変更で塗る。何が変わるかを見せる図で使う
- つながり(`edges`): `from`・`to`・`label`・`change`(箱と同じ3つ)。判断(`decision`)の箱から出る線には、すべて `label` を付ける。手分けして並べるだけの枝には要らない
- 流れの図
  - 各箱から最初に書いた矢印を主な流れとして、一直線に通す。主な流れを先に書き、例外の枝を後に書く
  - `lanes` と `phases` は `{label, nodes: [箱の id]}` の配列。どの箱も、どれか1つに入れる
  - 向きは左から右が既定。縦(`direction: "down"`)は、箱が6個以下の短い流れにだけ使う。長い流れを縦にすると図が縦に伸び、横長の図より大きく表示されて、並べたときに揃わない
- 構成の図: `boundaries`(囲み)を `{label, nodes: [箱の id]}` で書く。囲みに入らない箱(外部の利用者など)は外に置かれる。つながりの元が左に並ぶ
- 比較の図: `before` と `after` に、流れか構成の図を1つずつ書く。題と説明は外側に1つだけ

ラベルは2行まで。横向きの図では1行に全角9字ほど、縦一列の流れでは15字ほど入る。箱は12個まで。超えるなら図を分ける。ここに無い項目は書けない(書き間違いに気づけるよう、知らない項目は指摘して止める)。

凡例・変更の印・比較の見出しは、生成器が題と説明の言語で書く。どちらかに日本語があれば日本語、無ければ英語になる。

## 書き出す

```bash
node <diagram>/scripts/diagram.mjs <図の JSON> -o <名前>.png -o <名前>.svg
```

拡張子で形式を選ぶ。`-o` は何度でも書ける。

- PNG: 貼るための画像。生成器が playwright-cli を呼び、2倍の大きさで撮る
- SVG: 文字のファイルなので、そのまま添付できる場所ではこちらを使う
- HTML: 図1枚を、ブラウザで原寸で開くためのページ

`--no-heading` を付けると、題と説明を図の中に描かない。載せる先に説明を別に書くときに使う。`--theme grid` を付けると、方眼の背景になる。

レーンのある横向きの図は折り返さない。幅が 2,400px を超えると、自動で縦のスイムレーンに切り替える。レーンの無い流れは、1行 1,600px で折り返す。段階(`phases`)があれば段階の境目でだけ折り返し、1行に入らない段階は行を延ばす。

playwright-cli が無ければ、PNG だけを飛ばし、ほかの形式を書き出して終了コード3で知らせる。PNG が要るなら、入れるかを相手に聞いてから入れる。無断で入れない。入れるのは `npm install -g @playwright/cli@latest` と `playwright-cli install-browser`(ブラウザは約150MB)。権限のエラーが出たら `sudo` は使わず、`PLAYWRIGHT_CLI="npx -y @playwright/cli@latest"` を付けて走らせる。

書き出したら PNG を開き、線とラベルが読めるかを自分の目で確かめてから人へ渡す。字幅は見積もりなので、Mac 以外の書体でははみ出すことがある。

## 指摘を直す

読めない図は作らず、直し方を返して終了コード1で止まる。使い方や JSON の読み込みの誤りは終了コード2、PNG を書き出せなかったときは終了コード3(ほかの形式は書き出す)。

| 指摘 | 直し方 |
| --- | --- |
| 箱が13個以上ある | 図を分ける。前後の段階や、変わらない部分を別の図にする |
| role・change が一覧に無い、「…」は書けません | 書き間違いを直す。書ける値と項目は指摘に並ぶ |
| ラベルが長すぎる | 言い換えて短くする。補足は `sub` へ移す |
| 矢印の先が無い | `from`・`to` を箱の `id` と合わせる |
| つながりのラベルが、箱の中の字に重なる | ラベルを短くする。説明が要るなら、箱の `sub` に書く |
| 折り返すと3本以上の線が切れ目をまたぐ | 図を分けるか、箱を減らす |
| 図の幅が 2,400px を超えた | 図を分けるか、箱を減らす |

長いラベルの指摘は、つながりの誤りを直した後で出ることがある。直したら、もう一度実行する。

## 変えたとき

このスキルは自分のフォルダの外を読まない。生成器を変えたら、テストを走らせる。

```bash
node --test <diagram>/tests/diagram.test.mjs
```

見本の JSON から出た SVG のハッシュを、保存したハッシュ(`tests/snapshots.json`)と比べる。構成の図は、線が交差も重なりもしないことも確かめる。見た目が変わった見本はテストが名前を出して落ちるので、PNG にして開き、読めるかを確かめる。意図した変更なら `UPDATE_SNAPSHOTS=1` を付けて走らせ、保存したハッシュを書き直す。
