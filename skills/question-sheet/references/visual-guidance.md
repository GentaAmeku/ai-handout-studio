# 判断を助ける図表

複数案の効果・費用・担当・制約を比べるなら比較表を使う。単純な希望や文章の修正なら図表は不要で、visualRationaleに理由を残す。主図は1問1つ、質問と回答の間へ置く。判断点の強調と、役割の異なる小さな補助表は併用してよい。説明文は図にない前提・判断点だけを書く。

| 判断したいこと | 使うもの | 絞り方 |
|---|---|---|
| 見た目・画面・配置・色の案 | イメージ画像(`images`) | 案ごとに1枚、1〜4枚。label は選択肢の名前と同じにする |
| 案ごとの違い | 比較表 | 同じ観点で各案を比べ、結論に関わる4行以内 |
| 手順・分岐・合流 | 流れ図 | 今回判断する分岐と前後の作業だけ |
| 構成・シーケンス・データの流れ・状態の移り変わり | Archifyの図の画像(`images`) | 判断に関わる部品と経路だけ。`caption`と`label`に何の図かを書く |
| 担当の分担 | 分岐と合流の図 | 誰が何を担当し、どこで受け渡すか |
| 単純な希望・文章の修正 | 短い本文 | 図を使わず回答欄を近くに置く |

見た目の案を選んでもらう質問では、比較表より先にイメージ画像を作って `images` を主図にする。言葉だけでは違いが伝わらない。画面やレイアウトの案は、HTML でモックを描いてスクリーンショットにする(作れる画面に近い)。写真調の絵や挿絵は、画像を生成できる手段で作る。作り方の順は ai-handout-studio スキルの「画像を用意する」と同じ。生成した画像やモックは、完成品と取り違えないよう `caption` か `label` に「イメージ」と書く。費用や手間の違いも比べたいなら、`detail` に書くか別の質問の比較表にする。

図が初期案を示すならそう明記する。回答を変えても図まで変わったように見せない。構成・経路を確かめる図は、Archifyで作って画像にし、`images`で載せる(作り方はSKILL.mdの「Archifyの図を載せる」)。操作できる全体図(`explorers`)は新しく作る質問票では使わない。

比較表は同じ粒度・中立な文言で書き、推奨案の欠点も省かない。2〜4列を使い、案ごとの違いが分かる観点を選ぶ。

回答欄は説明・図解・根拠の下へ置き、長文を省略しない。自由入力欄は内容に応じて高さを調整する。入力中に質問を再生成しない。
