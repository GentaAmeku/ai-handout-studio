# 開発フローや日常の相談へ組み込む

呼び出し元は質問の内容と、回答後に何をするかを決める。question-sheetは質問の表示、下書き、回答の回収と検査を担当する。Node.js 22以上とブラウザーが必要で、特定の業務管理ツールや別のスキルは必要ない。

## 共通指示へ書く文例

> 複数の未決事項をまとめて回答・修正する場面では、利用可能ならquestion-sheetを使う。短い即答は会話で済ませる。利用者が回答形式を指定した場合は、その指定を優先する。

AGENTS.mdやCLAUDE.mdにはこの使用条件を書き、実行手順を複製しない。両方を共通設定から作っている環境では、その管理元へ一度だけ書く。共通設定がない場合は使用するエージェントの指示ファイルへ書く。スキルを導入するだけでも利用でき、この追記は日常的に選ばれやすくするための任意設定である。

## 要件整理や設計で呼び出す

未決事項を洗い出した後に、判断が必要な質問を渡す。質問IDと版を付け、回答を検査してからIDで対応付ける。単一回答は編集後の文章を採用し、元の推奨へ戻さない。回答で解消しなかった点だけを追加で確認する。質問の作り方や設計合意の基準は、呼び出し元の手順に従う。

スキルが未導入なら会話で進める。ローカルサーバーが使えない場合は単体HTMLと回答JSONを使う。Node.jsがない環境では生成できないため、会話で回答を受け取る。

回答の返却を、保存・送信・実行の許可へ読み替えない。必要な承認は呼び出し元が管理し、別の段階の承認へ流用しない。
