# 質問票

既定のテンプレート(Cobalt)は1問ずつ読む骨格(focus)で、広い画面では質問一覧を開いた状態で始まり、全体と進捗を見渡せる。右上の「質問一覧を閉じる」で一覧を閉じると、広い本文で読める。`--layout all` にすると全問を1ページに並べ、申請フォームのように上から順に答える。説明・図解・根拠を読んだ後に、下の回答欄で答える。前へ・次へと進み具合は画面下に固定される。詳細と図は本文に表示する。1〜2件の短い即答は会話や組み込み質問で済む。複数件の読み比べ、回答の往復・保存、図の説明が役立つ場合にこの画面を使う。ユーザーが形式を指定したときはその指定を優先する。

## 質問を作る

質問は利用者の言語(`ai-handout-studio settings`の`locale`、または会話の言語)で書き、JSONの最上位に`lang`(`ja`か`en`)を書く。画面の文言(「回答をコピー」・推奨の印など)がその言語で出る。字数の目安など日本語の書き方の決まりは、日本語の質問票のときだけ当てる。

[形式と例](references/questions.md)を読み、質問JSONを作る。IDは質問の意味に結び付け、質問を変えるとrevisionも変える。単一回答は選択肢を並べ、「（推奨）」付きの回答文を入力欄の初期値にする。labelに(推奨)を書かない。推奨は`recommended`で示し、画面が「（推奨）」を付ける。選択肢を選ぶと文が入り、そのまま編集できる。利用者はその文章へ条件も書き込めるため、補足欄を重ねない。複数選択はチェックボックスを使う。開いた質問から移動すると、有効な回答は入力済みになる。未表示の質問は入力済みにしない。説明は短く、根拠を本文へ置く。単純な希望や文章の修正なら図は不要。複数案の費用・効果・影響・担当を比べる質問は比較表にする。必要な場合は判断点を強調した図と小さな補助表を使う。違いだけなら比較表、単純な分岐・合流なら従来の構造化図でよい。見た目・画面・配置・色の案を選んでもらう質問は、案ごとのイメージ画像を作って`visual.type: images`で並べる(画面の案はHTMLでモックを描いて撮る。[見本](examples/images.json))。構成・シーケンス・データの流れ・状態の移り変わりの図が判断に要る質問は、Archifyで作った図の画像を`visual.type: images`で載せる(下の「Archifyの図を載せる」)。図で伝わる内容を文章で繰り返さない。[図表の使い分け](references/visual-guidance.md)を読み、判断に必要な図だけを置く。

画面のスタイル(ai-handout-studio の質問票のテンプレート)と簡単な図の生成器は、このスキルが入っているリポジトリの `design/dist` から読む(リポジトリで `pnpm install` を実行したあとに使える。無ければ `render`・`serve`・`audit` がそう伝えて止まる)。`render`・`serve` の見た目は `--template <名前か tokens の CSS のパス>` で選べ(`cobalt`: Cobalt、`default`: Default、`paper`: Paperなど。一覧は `design/dist/sheet/templates.json`)、省くと ai-handout-studio で質問票の既定に選ばれたテンプレートを使う。画面の骨格は `--layout` で選ぶ。省くとテンプレートの骨格(既定のテンプレートの Cobalt なら `focus`、1問ずつ)。長い説明や図を1問ずつ読ませたいときや、質問が多く(8件以上)進捗を見せ続けたいときは `focus`(1問ずつ。広い画面では質問一覧を開いて始まる)、短い確認は `all`(全問を縦に並べてその場で答える)、紙やPDFで渡す・読み合わせるときは `print`(書き込み用紙。`render` だけで使い、回答は画面から返せない)。Node.js 22以降とブラウザーが必要。以下の`<skill>`は、このSKILL.mdがあるディレクトリの絶対パスへ置き換える。

## Archifyの図を載せる

Archifyは別作者のスキルとして利用し、同梱しない。構成・シーケンス・データの流れ・状態の移り変わり・戻りのある流れの図が要るときは、`ai-handout-studio`コマンドの`diagram`でArchifyの図を画像に書き出し、`visual.type: images`で載せる。手順(Archifyの場所の調べ方・specの書き方・`ai-handout-studio diagram <種類> <spec.json> --out <画像>`)はai-handout-studioスキルの「図を載せる」に従う。`caption`と画像の`label`に何の図かを書く。単純な分岐・合流の流れは、従来どおり`visual.type: flow`(同梱の生成器)を使う。

Archifyが無い(`node <skill>/scripts/archify.mjs`がexit 1、または`diagram`がexit 3)ときと、`ai-handout-studio`コマンドが無いときは、図なしで作る(比較表や文章にする)。Archifyが無いときは、仕上げの報告の最後にArchifyの紹介を1行添える(入れ方`npx skills add tt-a1i/archify -g`と、入れると載せられる図の種類)。同じ会話で2回は紹介しない。無断でインストールしない。

操作できる全体図(`explorers`。HTMLを埋め込む形)は、ai-handout-studioに保存した質問票では中身が描かれない。新しく作る質問票では使わない。古い質問票を読めるよう、形式と描画は残している([全体図の形式](references/explorers.md))。

## 読むための組み立て

本文は17px、字間0.03em。長い説明を見出しにせず、`detail`に置く。段落は空行で分ける。図・表・回答は最大1280pxの画面幅を活かし、説明文だけ行幅を制限する。長文を1画面へ無理に縮めない。

検証の成功・参考情報・注意点は、本文に埋めず、根拠がある場合に`notices`で示す。緑・青・琥珀色に記号とラベルが付く。選択肢の推奨を成功と呼ばない。絵文字は意味を補う少量にとどめ、色だけで判断させない。

## 提示前に組み立てを確かめる

[完成例](examples/reading.json)は、長文・4列の比較表・状態表示・注意欄・Archify・回答を組み合わせた合成資料。形だけを参考にし、値や結論は実資料から書く。例の全体図(`explorers`)は古い形なので写さず、Archifyの図は画像(`images`)で載せる。

1. 質問ごとに「何を比較して決めるか」を定める。案ごとの違いは`visual.type: comparison`へ整理し、前提と理由は`detail`に段落で書く。表にある文を本文へ繰り返さない。
2. 成功は見出し横の緑、注意は表の後の琥珀色、参考情報は青に分かれる。事実がなければ成功を作らない。絵文字・記号は意味を見分けるために使う。
3. 選択肢があるのに表も図も不要な場合だけ、`visualRationale`に理由を書く。たとえば単純な希望の確認、同じ文章の修正。これは作成側の判断記録で、画面には表示しない。
4. 次の検査が通るまで質問JSONを直す。通常のrender/serveは既存資料との互換性のため生成を止めないが、警告を無視して提出しない。

```bash
node <skill>/scripts/sheet.mjs audit <questions.json>
```

生成後は長文のある代表質問を開き、見出し・比較表・状態と注意・回答が読み分けられることを確認する。色のCSSが入っているだけでは完了にしない。文字を極端に小さくせず、図表と編集欄が本文の下にあることも見る。

## ai-handout-studio に資料として残す

`ai-handout-studio`コマンドがある環境では、質問票を資料として保存する。資料一覧に並び、あとから意匠を替えて1枚のHTMLに書き出せる。コマンドが無ければこの節は飛ばし、これまでどおり`render`か`serve`で渡す(コマンドを入れるなら、リポジトリのSETUP.mdのとおりに入れる)。

```bash
ai-handout-studio sheet new --questions <questions.json> [--template <名前>] [--layout <focus|overview|all|print>]
```

`--layout` は質問票ごとの並べ方で、`focus`(1問ずつ。一覧を開いて始まる)・`all`(全問を並べる)・`print`(紙に書き込む)から選ぶ。`overview` は `focus` と同じに描く(前からの指定を読めるように残している)。省けばテンプレートのレイアウトになる。あとから替えるなら`ai-handout-studio sheet update <id> --layout <…>`(質問はそのまま)。

`id`・資料の1件を開く`url`・質問票を原寸で開く`readUrl`が返る。利用者へ伝えるのは`id`と`readUrl`で、保存したら`ai-handout-studio open <id>`を実行し、出力に`lanReadUrl`(同じWi-Fiのスマホで開くURL)があれば並べて伝える。LANに開くかは設定(`features.lan`)で決まる。`open`が`restart`を促したら、それを実行する。利用者が共有のWi-Fiにいると言ったときは`--no-lan`を付ける。`readUrl`(`/api/sheets/<id>/preview`)は1枚の質問票をそのままの大きさで開き、質問の前へ・次へも動く。`url`(`/sheets/<id>`)は資料の1件のページで、見本を縮めて出すため字が小さい。テンプレートの入れ替えと書き出しに使うので、必要なときだけ添える。`readUrl`の画面には「回答をコピー」があり、答えた内容がMarkdownになる。利用者がそれを会話へ貼るので、回答サーバーは立てない。質問を直したら`ai-handout-studio sheet update <id> --questions <questions.json>`、利用者が回答を会話へ貼ったら、`ai-handout-studio sheet answers <id> --answers <answers.json>`で同じ資料へ必ず残す。あとで質問票を開くと、答えた内容が入った状態で出る(別のブラウザでも、書き出したHTMLでも)。回答JSONの形は[形式と例](references/questions.md)にある。貼られたMarkdownの見出し`## 題 (質問ID)`で質問を、項目名で選択肢IDを対応付け、曖昧な対応は確定せず利用者に確かめる。版(`revision`)が質問と合っていない回答は断られる。答えている途中の入力は、画面がブラウザの中に残すのでリロードしても消えない。

保存先は`ai-handout-studio`の`workspace/`で、質問と回答そのものが入る。会話の内容を含むため、その業務の規則に従って扱う。

## 表示して回答を受け取る

```bash
node <skill>/scripts/sheet.mjs serve <questions.json> --out <answers.json>
```

バックグラウンドで起動し、標準出力のローカルURLを開く。回答先は新しいファイルにする。待機中も他の作業は続けられる。既定は30分で終了し、回答受領は終了コード0、中断は130、期限切れは2。プロセス終了を確認して回答ファイルを読む。ブラウザー内の下書きは同じ接続先で復元できる。サーバー再起動や別端末で続ける場合は「下書きを保存」でJSONを持ち出す。

サーバーを使えない環境では単体HTMLを生成し、開いてもらう。

```bash
node <skill>/scripts/sheet.mjs render <questions.json> --out <sheet.html>
```

「回答一覧」から回答JSONを保存、またはMarkdownをコピーして会話へ返せる。下書きJSONはファイルを移しても同じ質問群へ読み込める。

## 回答を使う

```bash
node <skill>/scripts/sheet.mjs validate <questions.json> --answers <answers.json>
```

全件、版、必須入力の検査が通ってから使う。順番でなく質問IDで対応付ける。単一回答はtextが正本。selectedが空でも有効な自由回答であり、推奨の選択IDへ戻して解釈しない。Markdownだけが返った場合も全件と版を確認し、曖昧な対応は確定しない。保存・コピー・「回答を返す」は回答の返却であり、外部操作の許可を追加しない。業務側で必要な承認はその手順に従う。開発フローなどへの組み込みは[接続規則](references/integration.md)を読む。

生成HTMLや回答には会話の内容が入る。配布ZIPには合成の見本だけを含める。回答完了後の保持・削除は、その業務の規則に従う。
